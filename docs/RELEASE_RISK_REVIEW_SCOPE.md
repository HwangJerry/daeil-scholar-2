# 추가 배포 위험 검토 — 테스트 계정 범위

2026-09-07, 기준 후보 d1d1cbef415fa36815c408eaef29b0967357aad9.

## 발견 및 보완

P1: `ACCOUNT_ERASURE_TEST_USER_SEQ`를 직접 설정할 때 `42x`, 빈 문자열,
정수 범위를 넘는 값을 입력하면 일반 정수 환경변수 로더가 기본값 0을 반환했다.
0은 전체 회원 범위이므로 활성화된 서버에서는 의도한 테스트 제한이 사라질 수 있었다.
CLI의 양수 검증은 이 직접 설정 경로를 보호하지 못했다.

실제 `config.Load()`를 호출하는 회귀 테스트에서 세 입력이 모두 0으로 변환됨을 재현했다.
해당 설정에 전용 로더를 적용했다. 미설정은 기존 의미인 0, 명시된 유효 정수는 해당 범위를
유지하며, 잘못된 입력은 유효성 검사에서 거부한다. 음수도 거부한다.

## 남은 운영 리스크

- 배포는 Apache/백엔드를 중지하므로 서비스 중단이 있다. 운영 데이터에서 058 변환 및
  백업에 걸리는 시간은 아직 측정하지 않았다.
- DB DDL은 일부 적용될 수 있으며 자동 원복하지 않는다. 앱 파일 원복이 DB 복구를
  대신하지 않으므로 실제 복구 가능성과 점검 시간 확보가 필요하다.
- 중지/활성화 검증 실패 시 안전을 위해 백엔드를 중지한다. 담당자의 복구가 필요할 수 있다.
  프로세스 강제 종료/호스트 장애도 자동 원복 완료를 보장할 수 없는 조건이다.
- 파일 참조 검사는 DB 범위를 잠근다. 운영 부하에서 지연을 확인해야 한다.
- 실제 실행 계정의 파일 권한, 암호화 키와 외부 처리 설정, 실기기 및 소셜 제공자 탈퇴는
  로컬 검증으로 대체할 수 없다. 전체 활성화 전에 일회용 계정으로 확인해야 한다.
- 외부 처리와 영수증 업무의 완료 증빙은 운영자가 확인해야 한다. 10일의 암호화 처리
  문맥 만료 전에 처리해야 하며, 만료 후에는 별도 원본 확인이 필요하다.

이번 검토/보완에서 운영 연결, 배포, 설정 변경, 실회원 삭제는 하지 않았다.
