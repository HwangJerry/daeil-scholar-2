# Push PR Gate

Version: 1.0  
Last Updated: 2026-06-11  
Owner: Tech Lead + QA Lead + SRE

이 문서는 Push 관련 변경사항 PR 병합 조건을 정의한다.
해당 체크리스트 미충족 시 merge는 금지한다.

## 1) 필수 체크리스트

- [ ] `docs/push/contract.md` 최신 반영
- [ ] `docs/push/policy.md` 최신 반영
- [ ] 변경된 푸시 이벤트 타입/스키마에 대한 Contract Test 갱신
- [ ] 관련 QA Matrix 항목 추가/수정 (아래 10항목 커버)
- [ ] Runbook 링크 첨부 (`docs/push/runbook.md`의 해당 시나리오 번호)
- [ ] 모니터링 패널/알람 룰 변경 이력 첨부
- [ ] 보안 검토 승인(토큰/링크/PII 정책)
- [ ] 장애 대응 책임자 지정

## 2) 자동화 체크(필수)

CI에 다음 단계가 반드시 포함되어야 한다.

1. Contract/Schema lint
2. 보안 lint(PII 키워드 + 허용되지 않은 payload 키 검사)
3. 단위 테스트
4. 통합 테스트
5. Push E2E 시나리오 테스트
6. Lint/포맷 검사

실패 시:
- 자동 코멘트: 해당 단락에 실패 사유 링크 자동 첨부
- `fail` 상태에서 merge 불가

## 3) 항목별 종료 조건과 매핑

각 PR은 아래 10개 이슈 중 적어도 2개 이상이 영향을 받으면 해당 항목의 DoD 증빙을 제출해야 한다.

1. 토큰 관리  
2. 중복 알림  
3. 보안/PII  
4. iOS 백그라운드  
5. 오프라인 정합성  
6. 다국어/시간 처리  
7. 테스트 게이트  
8. 모니터링 대응  
9. 동의/철회 정책  
10. App Store 정책

## 4) 산출물 템플릿

### PR 설명(요약)
- 변경 목적:
- 영향 범위:
- 관련 이벤트 타입:
- 데이터 마이그레이션:
- 배포 롤백 계획:

### 증빙
- Contract Test: 링크
- Security Scan: 링크
- QA 결과: 링크
- 운영 데시보드: 링크
- Runbook 항목: 링크

## 5) 예외 정책

- 보안 취약성, 동의/철회 정책, 알림 규격 변경은 `예외 없이` 차단 규칙을 적용한다.
- 임시 우회는 스프린트 단위의 승인 티켓 + 1주 내 복구 계획 포함 시에만 허용.
