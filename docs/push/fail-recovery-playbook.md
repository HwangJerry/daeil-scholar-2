# 실패/재오픈 Playbook (Push 10가지 고민)

목표: “완료처럼 보이지만 증빙이 없는 상태”가 배포되지 않게 한다.

## 1) 실패 분류

### A. PR Gate 실패
- 사유: 템플릿 미작성, 증빙 누락, 걱정 항목 미체크, Runbook 미기재
- 처리:
  1) PR 작성자에게 즉시 리마인드
  2) 누락 항목 한정 패치
  3) `re-run` 기준 충족 후 재심사

### B. QA/보안 실패
- 사유: 테스트·보안 정책 불통과
- 처리:
  1) 재현 로그/스크린샷 첨부
  2) 원인 분리(계약/정책/코드/인프라)
  3) 수정 후 재실행

### C. 운영 Runbook 미대응
- 사유: 경보 대응 이력 누락
- 처리:
  1) 대응 티켓을 즉시 생성
  2) 조치 항목과 종료 시각 기록
  3) Close는 대응 완료 후만 허용

## 2) 재오픈 판정 규칙

다음 조건 하나라도 만족하면 `Closed` → `Reopen`:
- DoD 수치 미달
- 증빙 링크 미제출 또는 잘못된 링크
- PR Gate 통과 전 증빙 변경
- 대응 로그가 7일 내 미작성

`Reopen` 처리 형식:
- 항목 번호
- 누락 근거
- 수정 액션
- 다음 기한
- 담당자

## 3) 예외 정책
- P1 경로, 보안 이슈, 정책 미준수는 절대 예외 없음
- hotfix 예외는 `critical` 라벨 + Tech Lead 승인 + 24시간 내 복기 보고서 작성

- [ ] 최종 Close 승인자:

## 5) 주간 운영 회고 규칙
- 해당 주 Reopen 수량 0 목표
- 재오픈 누적이 2회 초과한 항목은 소유자 R/A 재배치
- 공통 원인이 2개 이상 반복되면 정책/테스트 중 하나를 추가 수정
