# 계정 삭제 저장소 확인과 연락처 보존 기준안

2026-09-07. 운영 서버는 읽기 전용으로 조사했다. 백업 생성·삭제, 운영 DB 수정, 배포는 하지 않았다.

## 서버 백업 확인 결과

- 황제철 담당자 확인: 가비아 자동 백업·스냅샷 사용 안 함. 서버 전체를 컨테이너 이미지 형태로 보관할 계획은 있으나 아직 실행하지 않음.
- `/var/backups`에는 `alumni-maintenance`만 보였다. 해당 디렉터리는 약 48KB이며 하위 디렉터리 3개다.
- 목록에 있는 파일은 `alumni-backend.env`, manifest, Apache 설정, 레거시 PHP 설정 스크립트와 존재 여부 표식이다. 파일 목록에서 DB 덤프·회원 업로드 사본·서버 이미지는 발견되지 않았다. 환경설정 값이나 인증정보를 출력·복사하지 않았다.
- 앞서 확인한 systemd timer, cron.d, cron.daily/weekly 목록에서는 앱 백업 작업을 발견하지 않았다. 이번에 확인한 root crontab에는 시간 동기화 `rdate`와 PHP 정기결제 배치 실행 2개가 있다.
- PHP 배치는 `/var/www/html/_sys/payment/profile/mobile/_profile_batch.php`이며 외부 파일을 include한다. 해당 파일의 백업 관련 키워드 검색은 일치하지 않았다. 이것만으로 포함 파일의 전체 실행 효과나 실제 정기결제 수행 여부까지 확인한 것은 아니다.

판정: 확인한 유지보수 디렉터리를 회원 데이터 백업으로 간주할 근거는 없다. 사용자 확인상 가비아·서버 이미지 백업도 없다. 다만 서버 전체·개인 PC·외부 저장소를 전수 조사한 결과가 아니므로 모든 백업이 영구적으로 없다고 증명한 것은 아니다. 해당 확인 범위의 근거를 유지하되 운영 요청의 `backups` 상태를 이번 작업에서 직접 변경하지 않았다.

현재 사용하지 않는 서버 이미지 백업을 위해 새 백업 시스템을 출시 전 필수로 구축할 필요는 없다. 실제 백업을 도입하기 전에 보관 대상·기간·만료 및 복원 시 탈퇴 데이터 재삭제 방식을 함께 설정한다. 실제 회원 백업이 없는 것으로 확인되는 범위는 `not_applicable` 근거로 사용할 수 있으나 미래 요청에 무기한 재사용하지 않는다. Sentry 공급자 백업은 서버 백업과 별개다.

컨테이너 이미지는 서버 전체 백업과 동일하지 않다. 특히 `docker commit`에는 마운트된 볼륨 데이터가 포함되지 않는다. 향후 백업 설계 시 DB·업로드 볼륨을 별도 확인한다. [Docker 공식 문서](https://docs.docker.com/reference/cli/docker/container/commit/)

## 기부 자료의 확정 사실

- 해피나눔 영수증은 디지털 발급 및 시스템 원본 보관.
- 계좌이체 원본은 별도 엑셀 보관. 구체적인 저장 매체·접근 통제까지 확인한 것은 아니다.
- 운영자는 탈퇴 후 영수증 발급 등을 위한 연락처 보존을 요청했다.
- 엑셀의 일괄 날짜는 등록일이다. 이를 실제 기부일·영수증 발급일로 간주하지 않는다.

## 연락처 보존 기준 — 운영자 채택

1. 법정 보존 대상인 실명·거래 증빙은 적용 근거와 실제 기산일에 따른 기간 동안 별도 보관한다. 기부자별 발급명세의 법정 보존 의무를 모든 연락처의 5년·10년 보존 의무로 확대하지 않는다.
2. 연락처는 구체적으로 진행 중인 영수증 발급·정정·재발급 업무와 결과 전달에 필요한 범위로 한정하고, 해당 업무·결과 전달 완료 후 지체 없이 정리하는 기준을 권한다. 시작일·담당자·업무 내용·종료 판단을 기록한다. 단순히 '향후 필요할 수 있음'만으로 미완료 업무를 계속 유지하지 않는다.
3. 종료 이후 새 재발급 요청이 오면 그 요청을 처리하는 데 필요한 본인 확인·연락 정보를 다시 접수하는 방안을 사용한다.
4. 별도 엑셀·해피나눔에 보관한다는 이유만으로 앱 삭제 요청과 무관한 자료로 단정하지 않는다. 독립적인 기부 업무와 앱 회원 서비스의 범위, 수집·보존 근거를 구분해 확인한다. 기존 연락처를 앱에 추가 복사하여 장기 보존하는 구현은 하지 않았다.
5. 운영자는 진행 중인 영수증 업무와 결과 전달 완료 후 연락처를 삭제하는 기준을 채택했다. 미완료 업무를 위한 탈퇴 후 보관의 적법성 또는 Apple 삭제 예외까지 자동으로 확정하는 것은 아니다. 실제로 적용할 근거를 확인한 뒤 방침·삭제 동작과 일치시킨다.

근거: [개인정보 보호법 제21조](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1027063705)는 불필요해진 개인정보의 파기 및 법정 보존 자료의 분리 관리를 규정한다. [소득세법 시행령 제208조의3](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1032472419)의 기부자별 발급명세 항목에는 성명 등과 기부금액·기부일자·발급일자가 있으며 연락처의 일괄 장기 보존 의무를 이 조항에서 확인하지 못했다. [Apple 계정 삭제 안내](https://developer.apple.com/support/offering-account-deletion-in-your-app/)는 법적으로 유지해야 하는 자료를 삭제 예외로 설명한다.

채택된 기준은 migration 061의 영수증 업무 확인과 기존 관리자 삭제 화면, 공개 방침·접수증에 반영했다. 외부 원본의 실제 연락처 정리는 담당자가 수행하고 증빙을 등록한다. 앱이 엑셀이나 해피나눔을 직접 수정한다고 주장하지 않는다.

## 과거 파일·로그 추가 확인 — 2026-09-07

운영 서버를 다시 읽기 전용으로 확인했다. `/var/www/uploads`와 실제 레거시 `/var/www/html/upload`에서 깊이 2 이내 일반 파일은 각각 76개·364개였다. 회원별 소유권 목록이 아니며 두 레거시 경로를 별도 사본으로 세지 않는다. `alumni-backend` 계정으로 두 루트의 쓰기 가능 여부가 참이었다. 실제 하위 파일 삭제·권한 변경은 수행하지 않았다.

소스의 요청 로그가 실제 URL을 기록하므로 회원/메시지 번호와 파일명이 남을 수 있었다. 새 요청 로그·panic 로그는 등록된 라우트 템플릿을 사용하며, panic 값 원문은 로그/Debug Agent에 전달하지 않도록 수정했다. 기존 로그를 삭제한 것은 아니며 다른 서비스 로그의 전송 내용까지 최소화됐다고 판정하지 않는다.

PG 감사 로그는 승인 응답의 카드 번호·거래 식별자와 오류 문자열을 저장할 수 있다. Apache 설정의 `combined` 로그는 별도 경로다. Debug Agent는 설정 시 외부 오류 전송을 한다. 실제 활성 여부·수신 자료와 법정 보존 대상 거래 증빙을 확인한 뒤 처리해야 하므로 `external_data`/`other_identifiers`를 이번 작업에서 완료하지 않았다.

확인된 과거 업로드를 실제 삭제 작업에 연결하는 도구와 제한은 [운영 절차](HISTORICAL_FILE_ERASURE_RUNBOOK.md)에 기록했다.

실행 중인 백엔드 프로세스의 환경 변수는 값 원문 없이 설정 여부만 확인했다. `DEBUG_AGENT_ENDPOINT`, `SENTRY_AUTH_TOKEN`은 설정되어 있다. `ACCOUNT_ERASURE_EXTERNAL_URL`, `ACCOUNT_ERASURE_EXTERNAL_TOKEN`, `ACCOUNT_ERASURE_CONTEXT_KEY`, `DONATION_ARCHIVE_KEY`, `ACCOUNT_ERASURE_LEGACY_ROOT`는 미설정이다. 기존 프로세스 관측이며 아직 배포하지 않은 코드의 동작을 증명하지 않는다.

Sentry의 [프로젝트 오류 이벤트 조회 API](https://docs.sentry.io/api/events/list-a-projects-error-events/)로 출시용 두 프로젝트를 `statsPeriod=14d` 범위에서 읽기 전용 조회했다. `daeil-ios-release`, `daeil-android-release` 모두 오류 이벤트 0건이며 추가 페이지가 없었다. 인증 토큰·이벤트 원문은 출력·저장하지 않았다. 이 결과는 해당 조회 시점/범위의 오류 이벤트에 한정한다. 다른 데이터 유형, 공급자 백업, 향후 Release 페이로드의 개인정보 유무까지 검증한 것은 아니다.
