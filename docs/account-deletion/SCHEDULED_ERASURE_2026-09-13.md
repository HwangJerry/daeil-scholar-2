# 예약 탈퇴 / 관리자 조기 실행 구현

## 실행 계약

- 접수 즉시 이용 정지와 전체 로그아웃. 신청 취소는 이번 범위에 없음.
- ACCOUNT_ERASURE_WAIT_HOURS를 1..720시간 범위로 명시해야 활성화 가능. 기본 0은 설정 누락을 의미하며 활성화를 거절한다. 72시간은 테스트 값이지 운영 결정이 아니다.
- 신규 요청의 scheduledAt은 최초 접수 시 고정. targetAt은 구버전 호환용 같은 시각. dueAt은 예정 시각 + 10일의 결과 안내 기한이며 완료 보장은 아니다. 자동 실행이 늦어지면 기한을 자동 연장하지 않는다.
- 예약과 NEXT_ATTEMPT_AT(재시도)을 독립적으로 검사. 재개·인계·증빙 갱신으로 미래 예약을 우회하지 않는다.
- 관리자 expedite는 예약을 삭제하지 않고 expeditedAt/expeditedBy를 최초 한 번 기록한다. 공통 워커가 다음 주기(현재 1분)에 작업을 시작하며 API 응답이 삭제 완료를 뜻하지 않는다.
- 조기 실행, 예약 적용, 재시도, 처리 방식 전환은 워커의 DB named lock과 직렬화한다. 자기 계정의 관리자 처리는 거절한다.
- 기존 요청에는 migration 066이 자동 일정을 넣지 않는다. 관리자가 일정 적용 또는 조기 실행을 명시하기 전까지 워커 대상에서 제외한다. migration을 반복해도 신규 예약을 바꾸지 않는다.

## 단계와 수동 작업

소셜 철회 → 기부/영수증 검토 → 외부 작업용 암호화 자료 보관 → 수동 외부 인계 확인 → 내부 DB → 로컬 파일 → 외부 증빙 → 최종 완료.

- Kakao 예약 탈퇴는 서버 저장 사용자 ID와 서버 전용 KAKAO_ADMIN_KEY(Unlink 권한)를 사용한다. 단기 액세스 토큰 만료와 독립적이다. 응답 ID가 요청 대상과 일치해야 성공으로 인정한다.
- 공식 근거: https://developers.kakao.com/docs/en/kakaologin/rest-api#unlink
- Apple은 기존 암호화 refresh token 철회 경로를 유지한다. 실제 운영 토큰과 키를 검증해야 한다.
- 제공자 호출 성공 이후 로컬 마무리 실패의 재시도 한도 초과는 FINALIZE_FAILED로 남겨, 관리자 재시도 시 제공자 호출을 반복하지 않는다. 과거 FAILED는 어느 단계에서 실패했는지 운영 증빙 확인이 필요하다.
- 수동 외부 처리에서는 네 저장소 항목마다 담당자/처리 경로의 인계 근거(manual)를 등록해야 내부 삭제 가능. manual은 완료가 아니다. 완료/자료 없음에는 실제 증빙이 필요하다.
- 기존 HTTP 외부 처리 계약도 계속 사용 가능. 새로운 Sentry/백업 자동 삭제 공급자를 구현하거나 운영에 연결한 것은 아니다.
- 기부 보존 결정/영수증/정기결제의 기존 검사 및 관리자 업무는 유지. 해결 전에는 완료를 막는다. 보존 정책을 자동으로 추정하거나 정기결제를 강제 삭제하지 않는다.

## 콘텐츠 처리 기준

|대상|처리|
|---|---|
|탈퇴 회원 게시글|본문·제목·이미지·첨부 참조·등록자 정보 제거, 작성자 0의 삭제 안내 행 유지|
|그 게시글의 다른 회원 댓글·좋아요|보존|
|탈퇴 회원이 작성한 댓글·좋아요|기존 삭제 동작 유지|
|탈퇴 회원과 주고받은 쪽지|기존 대화 삭제 정책 유지; 상대방에서도 해당 대화가 사라짐|
|레거시 게시글 행 안에 포함된 답변(RE_CONTENTS)|작성자를 분리할 수 없으므로 자동 삭제 차단. 관리자 검토 후 분리 필요|
|프로필·명함·과거 업로드|기존 소유권/공유 참조 검사 통과 후 삭제|
|기부 기록|검토된 보존 결정에 따라 별도 암호화 보관 또는 삭제|

일반 회원 콘텐츠에 임의 익명 처리 정책을 추가하지 않았다. 쪽지 정책은 기존대로 유지했다. 다른 회원의 자유 텍스트에 인용된 개인정보는 간접 참조 수동 검토 대상이다.

## 배포 및 활성화 전 확인

1. 새 migration 066과 후보 해시를 검토. 기존 058의 파일과 이전 후보 manifest가 불일치했고 064/065도 목록에 없어서 현재 파일 기준 로컬 후보 목록을 갱신했다. 기존 migration SQL은 수정하지 않았다. 이 갱신은 운영 migration 승인/적용이 아니다.
2. 대기 시간, 서버 Kakao admin key, Apple 설정, 외부 저장소 담당자를 확인. 운영 비밀값은 이 문서에 기록하지 않는다.
3. 일회용 회원 범위로 API 접수, 소셜 제공자 실제 철회, 파일, 기부 보존, 외부 증빙, 최종 접수증까지 확인.
4. 기존 미완료 요청은 개별 검토 후 예약 또는 조기 실행. 설정 변경 시 예정 시각 재계산 없음.
5. 전체 활성화와 보관 만료 작업은 독립적으로 유지. 이번 구현은 운영 설정을 변경하거나 삭제 요청을 실행하지 않았다.
