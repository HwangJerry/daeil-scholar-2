# 탈퇴 회원 기부 증빙 열람

관리자 메뉴 ‘탈퇴 회원 기부 증빙’(`/admin/donation-archives`)에서 최고 관리자(root)가
보관 번호·근거·종료일 목록을 확인하고 목적을 선택하여 개별 증빙을 열람한다.
서버에서 기존 V1 AES-256-GCM 형식으로 복호화한다. operator와 일반 회원은 거절된다.

## 적용 조건

배포 전에 `064_create_donation_archive_access.sql`을 적용해야 한다.
서버의 `DONATION_ARCHIVE_KEY`는 기존 자료를 암호화한 키여야 한다.
키 재생성이나 단순 교체는 기존 자료를 읽지 못하게 한다.
이번 로컬 구현 작업은 운영 마이그레이션·키 변경·배포를 실행하지 않았다.

## 열람 기록

POST `/api/admin/donation-archives/{id}/read`에 목적 코드
`receipt_inquiry`, `accounting_review`, `official_request` 중 하나를 전달한다.
`ALUMNI_DONATION_ARCHIVE_ACCESS`에 보관 번호·운영자 번호·목적·UTC 시각을 기록한다.
커밋이 성공해야 원문을 반환한다. 이는 서버의 원문 제공 승인 기록이며 실제
브라우저 표시 여부까지 보증하지 않는다. 키 오류·변조·기한 만료·기록 저장 실패 시
원문을 반환하지 않는다. 기한은 기존 정리 작업과 같은 한국 날짜 기준이다.

응답은 no-store이며 원문은 React Query 캐시나 브라우저 저장소에 저장하지 않는다.
화면 메모리에만 보유하고 닫기·페이지 이동·탭 숨김 또는 5분 경과 시 제거한다.
브라우저 개발자 도구와 사용자 캡처까지 차단하지는 않는다.

기부 원본·암호화 보관 형식·전체 기부 통계는 변경하지 않는다.
이름 검색을 위해 전체 암호문을 복호화하지 않으며 보관 번호 순으로 탐색한다.
열람 기록 자체의 조회 화면과 자동 만료 정책은 이번 변경에 포함하지 않는다.
열람 기록에는 기부자 개인정보 원문이나 암호화 키를 기록하지 않는다.

## 검증 범위

Go 서비스·저장소·핸들러·서버 테스트, 관리자 화면 테스트 및 빌드.
운영 키로 실제 증빙을 읽는 작업 및 운영 DB 마이그레이션은 별도이다.
