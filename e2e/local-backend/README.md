# Local backend for mobile E2E (TS09)

All accounts, messages, posts, credentials and phone numbers here are **synthetic
and throwaway**. Never import production data or credentials. The checked-in
baseline contains schema only; it is the same baseline used by the TS07 harness.

## Prerequisites and commands

Use a local Docker daemon with Compose v2.30+ (or v5), Bash, Python 3, curl, jq and
Git. MariaDB 10.1.38 runs as `linux/amd64`, including on Apple Silicon. Ports
18080 (API) and 13306 (database) must be free. The first build needs network access
to download public images, Alpine packages and Go modules; subsequent unchanged
builds use Docker's cache. API tests run entirely locally, without external services.
If Docker is unavailable, scripts print `SKIP` and exit successfully without testing.

From the repository root (scripts also work from any other directory):

```bash
e2e/local-backend/up.sh       # build, start, wait for DB + API health, print accounts
e2e/local-backend/smoke.sh    # four HTTP checks; never prints tokens
e2e/local-backend/reset.sh   # destroy data, rebuild and reseed
e2e/local-backend/down.sh    # remove containers, network and volumes
python3 e2e/local-backend/test_guard.py -v  # offline safety regression checks
```

The Compose project is always `dflh-local-e2e`. The API and database bind only
to `127.0.0.1`. MariaDB data lives in a container tmpfs, with no persistent data
volume. Container recreation or database restart loses all changes. API uploads
and audit logs stay inside its disposable container. `down.sh` leaves the cached
API image and ignored `.build/` source context for the next build.

Diagnostics (synthetic local containers only):

```bash
docker compose --env-file e2e/local-backend/local.env -f e2e/local-backend/compose.yaml logs --tail=80
docker ps -a --filter label=com.docker.compose.project=dflh-local-e2e
docker volume ls --filter label=com.docker.compose.project=dflh-local-e2e
```

Use the scripts for lifecycle operations. They reject production-domain references
(including subdomains and mixed case) in the inherited environment, local config,
seed and resolved Compose config without printing values. They ignore other
Compose files/env-file overrides, require a local Unix-socket Docker endpoint,
and require loopback ports and local API integration targets.
No base URL override is accepted. curl ignores user config/proxies and follows no
redirects. The API starts with `NET_ADMIN` solely to remove its default route;
it can reach loopback and the connected database subnet, but has no route to the
internet. External DNS is disabled while Docker service-name resolution works.
This uses a regular bridge because Docker 29 does not publish ports for containers
attached only to internal bridges.

`up.sh` stages only tracked Go source, the two embedded HTML templates, Go module
files and an unchanged copy of `backend/Dockerfile`. This avoids sending env
files, keys, SQL dumps or other backend files to Docker. No production Dockerfile
or application behavior is changed.

## App configuration

- **iOS simulator:** In a Debug launch, set `DFLH_API_BASE_URL=http://localhost:18080`
  using the TS01 launch-environment override. This override is not for Release builds.
- **Android emulator:** The host URL is `http://10.0.2.2:18080`. Wiring the build
  property/flavor is future work in **TS11**; this task changes no Android code.
- **Host tools:** Use `http://127.0.0.1:18080`. Database access is
  `127.0.0.1:13306`, database `alumni_e2e`, user `e2e`, password `ts09-synthetic-db`.

The server's existing erasure-readiness validation requires an HTTPS
`SITE_BASE_URL`, so it is `https://localhost:18080` for generated receipt-link
metadata. The local stack serves **HTTP only**. Use the mobile receipt API
(`POST /api/account-deletion/receipt`) for E2E; generated HTTPS web receipt links
cannot be opened against this stack. This preserves production validation unchanged.

## Schema initialization

`init-db.sh` runs through `/docker-entrypoint-initdb.d` before TCP readiness:

1. Import `prod_baseline_schema_20260927.sql`, restoring mysql-client delimiters
   around its seven trigger definitions in a temporary copy.
2. Import `prod_baseline_applied_migrations_20260927.sql` (001–077).
3. Check each numbered repository migration against `_migration_history`. Skip
   matching applied files, fail on checksum drift, and apply/record missing files
   in filename order. New files must use the existing `NNN_name.sql` convention
   and mysql-client-compatible SQL. New production-domain references are rejected.
4. Apply `seed.sql`, including resetting both app-update policies to OFF.

The MariaDB digest and Barracuda/large-prefix/SQL-mode options match the test
harness. Initialization failure makes `up.sh` fail instead of serving a partial
database; inspect logs, correct the local files, then run `reset.sh`.
